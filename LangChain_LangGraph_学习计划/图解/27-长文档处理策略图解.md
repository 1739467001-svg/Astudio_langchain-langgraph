# 长文档处理策略图解

> 用图解理解当文档远超上下文窗口时的处理策略。

---

## 一、长文档的规模问题

```mermaid
graph TB
    subgraph 规模对比 {"文档长度 vs 上下文窗口"}
        SHORT["📄 短文档<br/>~3000字 ≈ 4500 tokens<br/>→ 直接传入 ✅"]
        MID["📋 中文档<br/>~30000字 ≈ 45000 tokens<br/>→ RAG分割处理 ✅"]
        LONG["📚 长文档<br/>~300000字(一本书) ≈ 450000 tokens<br/>→ 需要特殊策略 ⚠️"]
        HUGE["📖 超长文档<br/>~1000000字 ≈ 1500000 tokens<br/>→ 必须多级处理 ⚠️"]
    end

    LONG --> NOTE["GPT-4o-mini窗口128K<br/>一本书轻松超出3-10倍"]

    style SHORT fill:#C8E6C9
    style LONG fill:#FFE0B2
    style HUGE fill:#FFCDD2
```

## 二、Map-Reduce 摘要策略

```mermaid
graph TB
    DOC["📄 长文档<br/>(100页)"] --> SPLIT["分割为20段<br/>(每段~5页)"]

    SPLIT --> M1["段1 → LLM摘要<br/>~200字"]
    SPLIT --> M2["段2 → LLM摘要<br/>~200字"]
    SPLIT --> MN["...段N → LLM摘要<br/>~200字"]

    M1 & M2 & MN --> REDUCE["合并20个摘要<br/>~4000字"]
    REDUCE --> CHECK{"太长吗?"}
    CHECK -->|"是"| SPLIT2["再分割→再摘要<br/>(递归)"]
    CHECK -->|"否"| FINAL["最终摘要 ✅"]

    style SPLIT fill:#FFF9C4
    style REDUCE fill:#C8E6C9
    style FINAL fill:#C8E6C9
```

## 四、目录导航检索策略

```mermaid
graph TB
    Q["用户问题:<br/>'深度学习的原理是什么？'"] --> TOC["Step 1: 检索目录"]
    TOC --> FOUND["找到: 第3章 '深度学习原理'<br/>第3.2节 '神经网络基础'"]
    FOUND --> DEEP["Step 2: 只检索第3章的内容"]
    DEEP --> ANSWER["Step 3: LLM基于第3章回答"]

    NOTE["优势: 不在全文中检索(噪声多)<br/>先定位再深入(精准)"]

    style TOC fill:#FFF9C4
    style DEEP fill:#C8E6C9
    style NOTE fill:#E3F2FD
```

## 五、多遍处理策略

graph TB

## 六、策略选择决策树

```mermaid
graph TD
    Q1{"文档长度?"}
    Q1 -->|"<5000字"| S0["✅ 直接传入<br/>无需特殊处理"]
    Q1 -->|"5000-50000字"| S1["✅ RAG分割<br/>(chunk+向量库)"]
    Q1 -->|">50000字"| Q2{"需求?"}

    Q2 -->|"整体摘要"| M1["✅ Map-Reduce<br/>或层级摘要"]
    Q2 -->|"特定问题"| M2["✅ 目录导航<br/>先定位再检索"]
    Q2 -->|"深度分析"| M3["✅ 多遍处理"]
    Q2 -->|"问答系统"| M4["✅ 传统RAG<br/>(够用且经济)"]

    style S0 fill:#C8E6C9
    style M1 fill:#E3F2FD
    style M2 fill:#FFF9C4
    style M4 fill:#F3E5F5
```
