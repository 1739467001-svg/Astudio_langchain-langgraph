# 缓存策略图解

> 用图解理解 LLM 缓存的工作原理、语义缓存与精确缓存的区别、分层缓存架构。

---

## 一、缓存工作原理

```mermaid
sequenceDiagram
    participant U as 用户代码
    participant C as Cache层
    participant L as LLM API

    U->>C: invoke("什么是AI？")

    C->>C: 生成Key<br/>(模型+参数+Prompt的hash)
    C->>C: 查找Key

    alt 缓存命中
        C-->>U: 返回缓存结果（0ms）
        Note over C: ✅ 0秒 + 0 Token
    else 缓存未命中
        C->>L: 调用API
        L-->>C: 返回结果
        C->>C: 保存到缓存
        C-->>U: 返回结果
        Note over C: ⏱️ 3秒 + 1850 Token
    end
```

### 语义缓存的命中流程

```mermaid
graph LR
    Q["用户问题"] --> EMB["向量化<br/>(Embedding)"]
    EMB --> SEARCH["在缓存中<br/>搜索相似向量"]
    SEARCH --> CHECK{"相似度 > 阈值?"}
    CHECK -->|"是"| HIT["命中缓存 ✅<br/>返回缓存的回答"]
    CHECK -->|"否"| MISS["未命中 ❌<br/>调用LLM<br/>结果存入缓存"]

    style HIT fill:#C8E6C9
    style MISS fill:#FFE0B2
```

## 四、缓存 Key 的生成

```mermaid
graph TB
    subgraph Key组成 ["缓存Key由以下要素组合哈希生成"}
        K1["模型名称<br/>gpt-4o-mini"]
        K2["Prompt完整内容<br/>System+Human消息"]
        K3["temperature<br/>0 vs 0.7"]
        K4["max_tokens<br/>1000 vs 2000"]
        K5["其他参数<br/>top_p等"]
    end

    K1 & K2 & K3 & K4 & K5 --> HASH["SHA256哈希<br/>→ 缓存Key"]

    HASH --> NOTE["任一要素变化<br/>→ Key不同 → 缓存未命中"]

    style HASH fill:#FFF9C4
    style NOTE fill:#FFE0B2
```
