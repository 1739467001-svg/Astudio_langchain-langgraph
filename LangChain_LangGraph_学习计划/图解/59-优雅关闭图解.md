# 优雅关闭图解

> 用图解理解 LLM 应用的优雅关闭和零停机重启流程。

---

## 一、强制 vs 优雅关闭

```mermaid
graph TB
    subgraph 强制 {"❌ 强制kill"}
        K1["kill -9"] --> K2["请求中断"]
        K2 --> K3["用户500错误"]
        K3 --> K4["数据损坏"]
    end

    subgraph 优雅 {"✅ 优雅关闭"}
        G1["SIGTERM"] --> G2["停止新请求"]
        G2 --> G3["等待活跃请求完成"]
        G3 --> G4["保存状态→退出"]
    end

    style 强制 fill:'#FFCDD2'
    style 优雅 fill:'#C8E6C9'
```

## 二、零停机重启

```mermaid
sequenceDiagram
    participant LB as Nginx
    participant OLD as 旧实例
    participant NEW as 新实例

    Note over LB: 流量→旧实例
    NEW->>NEW: 启动并就绪
    NEW->>LB: 健康检查通过
    LB->>LB: 流量切换到新实例

    Note over OLD: 旧的收到SIGTERM
    OLD->>OLD: 停止接收新请求
    OLD->>OLD: 继续处理已有请求
    OLD->>OLD: 处理完成→保存→退出

    Note over LB: 全部流量→新实例
    Note over LB: ✅ 用户无感知
```

## 三、关闭状态流转

```mermaid
stateDiagram-v2
    [*] --> 运行中: 启动
    运行中 --> 排水中: 收到SIGTERM
    排水中 --> 排水中: 活跃请求>0
    排水中 --> 保存中: 活跃请求=0
    保存中 --> 已退出: 状态已保存
    已退出 --> [*]
```
