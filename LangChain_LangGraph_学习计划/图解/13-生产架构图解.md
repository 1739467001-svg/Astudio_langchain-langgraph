## 六、请求处理流程

```mermaid
sequenceDiagram
    participant C as 客户端
    participant N as Nginx
    participant A as FastAPI
    participant R as Redis
    participant L as LLM API
    participant D as 数据库

    C->>N: POST /api/chat (带JWT)
    N->>A: 转发请求

    A->>A: 1. 验证JWT
    A->>R: 2. 检查速率限制
    R-->>A: 未超限 ✓

    A->>R: 3. 检查缓存(相同问题)
    alt 缓存命中
        R-->>A: 返回缓存结果
        A-->>C: 返回缓存回答 (快速)
    else 缓存未命中
        A->>D: 4. 加载用户对话历史
        D-->>A: 历史消息
        A->>L: 5. 调用LLM(带历史)
        L-->>A: 生成回答
        A->>D: 6. 保存对话历史
        A->>R: 7. 缓存结果
        A-->>C: 返回回答
    end
```

## 十、成本与规模的平衡

```mermaid
graph LR
    subgraph 规模增长路径
        SMALL["小规模<br/><100用户<br/>单机Docker<br/>SQLite+FAISS<br/>月成本$50"] --> MID
        MID["中规模<br/>100-1000用户<br/>双机部署<br/>PostgreSQL+Chroma<br/>月成本$200-500"] --> LARGE
        LARGE["大规模<br/>1000+用户<br/>K8s集群<br/>PostgreSQL+Milvus<br/>月成本$1000+"]
    end

    style SMALL fill:#C8E6C9
    style MID fill:#FFE0B2
    style LARGE fill:#F3E5F5
```

| 规模 | 架构 | 数据库 | 向量库 | 月成本(估) |
|------|------|--------|--------|-----------|
| <100用户 | Docker单机 | SQLite | FAISS | $50 |
| 100-1K用户 | 双机部署 | PostgreSQL | Chroma | $200-500 |
| 1K+用户 | K8s集群 | PostgreSQL主从 | Milvus | $1000+ |
| 学习/原型 | 本地运行 | 内存/SQLite | FAISS | $10-20 |
