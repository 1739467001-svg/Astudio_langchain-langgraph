# 事件响应与根因分析图解

> 线上出问题了——先恢复服务再找根因。本图解可视化故障分类和五步根因法。

---

## 故障分类

```mermaid
graph TB
    FAIL["Agent故障"]

    FAIL --> Q["质量问题<br/>回答变差/幻觉"]
    FAIL --> P["性能问题<br/>延迟飙升/超时"]
    FAIL --> C["成本问题<br/>Token异常"]
    FAIL --> A["可用性<br/>API不可用/限流"]
    FAIL --> S["安全问题<br/>越狱/泄露"]

    style FAIL fill:#FFCCBC,stroke:#D84315,stroke-width:3px
    style Q fill:#E3F2FD,stroke:#1565C0
    style P fill:#FFF9C4,stroke:#F9A825
    style C fill:#F3E5F5,stroke:#7B1FA2
    style A fill:#C8E6C9,stroke:#2E7D32
```

## 五步根因法

```mermaid
graph TB
    S1["Step1: 确认故障"] --> S2["Step2: 恢复服务<br/>降级/回滚/切换"]
    S2 --> S3["Step3: 收集证据<br/>日志/指标/变更记录"]
    S3 --> S4["Step4: 形成假设<br/>可能根因列表"]
    S4 --> S5["Step5: 验证根因"]
```

## 事件分级

| 级别 | 影响 | 响应时间 | 行动 |
|------|------|---------|------|
| P0 | 全面不可用 | 5分钟 | 切备用+通知全体 |
| P1 | 严重降级 | 15分钟 | 排查+考虑回滚 |
| P2 | 部分受损 | 1小时 | 分析日志 |
| P3 | 轻微影响 | 4小时 | 记录待处理 |
