# 长上下文模型与 RAG 策略权衡指南

> Gemini 1.5 Pro 以 200 万 Token 上下文窗口震惊业界，Claude 3.5 支持 20 万，GPT-4o 支持 12.8 万。一个自然的问题浮现：上下文窗口这么大了，RAG 还需要吗？把所有文档塞进去不就行了？本指南系统分析长上下文模型与 RAG 的适用场景、成本权衡和混合策略，帮你做出正确的架构决策。

### "把文档全塞进去"可行吗？

```
场景：一个产品文档库，共 500 篇文档，平均每篇 2000 字

方案 A：长上下文直接塞
  总字数: 500 × 2000 = 100 万字
  Token 数: ~130 万
  → Gemini 1.5 Pro 可以（200万窗口）
  → 单次查询成本: ~$1.625（仅输入）
  → 每天查询 1000 次: $1,625/天

方案 B：RAG 检索 Top-5
  检索 5 篇 × 2000 字 = 1 万字 = ~1.3万 Token
  → 任何模型都可以
  → 单次查询成本: ~$0.03（输入+检索）
  → 每天查询 1000 次: $30/天

差距: 54 倍
```

## 2. 长上下文 vs RAG 全维度对比

### 能力对比

| 维度 | 长上下文（全塞入） | RAG（检索后生成） |
|------|-------------------|-------------------|
| 信息覆盖率 | 100%（所有文档都在） | 依赖检索质量（可能遗漏） |
| 回答准确性 | 高（不遗漏信息） | 中-高（取决于检索） |
| 成本/查询 | 极高（线性增长） | 低（固定 Top-K） |
| 延迟 | 高（处理大量 Token） | 低（只处理少量 Token） |
| 文档更新 | 不需要重建索引 | 需要更新向量索引 |
| 实现复杂度 | 低（直接拼入 Prompt） | 高（检索管线+分块+重排） |
| 可扩展性 | 差（受窗口限制） | 好（索引可无限扩展） |
| 引用溯源 | 需额外处理 | 天然支持 |
| 跨文档推理 | 强（全文可见） | 弱（只看检索片段） |
| 实时数据 | 需重新提交 | 增量更新索引 |
| 并发能力 | 低（大请求占用资源） | 高（轻量请求） |

### "Needle in a Haystack" 测试

```
长上下文模型的已知问题：

1. "中间遗忘"（Lost in the Middle）
   - 信息在上下文中间时，准确率显著下降
   - MIT 研究：中间位置准确率比首尾低 20-30%

2. 关键信息被淹没
   - 500 篇文档中只有 2 篇相关
   - 模型需要"扫描"全部内容找到相关的 2 篇
   - Token 越多，注意力越分散

3. 成本与延迟非线性
   - 10万 Token: 5秒，$0.25
   - 100万 Token: 30秒，$2.50
   - 延迟和成本随 Token 数线性甚至超线性增长
```

## 3. 决策框架

### 何时用长上下文（不用 RAG）

```python
@dataclass
class LongContextCriteria:
    """适合长上下文的判断标准"""
    total_docs_tokens: int          # 文档总 Token 数
    query_frequency: int            # 每日查询次数
    doc_update_frequency: str       # 文档更新频率
    need_cross_doc_reasoning: bool  # 是否需要跨文档推理
    max_acceptable_latency: float   # 最大可接受延迟（秒）
    budget_per_query: float         # 单次查询预算（美元）

    def should_use_long_context(self) -> tuple[bool, str]:
        """判断是否适合长上下文方案"""
        reasons = []

        # 条件1：文档总 Token 在窗口内
        if self.total_docs_tokens > 1_000_000:
            return False, "文档总量超出最大上下文窗口"

        # 条件2：查询频率低（高频太贵）
        if self.query_frequency > 100:
            return False, f"查询频率{self.query_frequency}/天太高，成本不可控"

        # 条件3：需要跨文档推理
        if not self.need_cross_doc_reasoning:
            return False, "不需要跨文档推理，RAG 更经济"

        # 条件4：延迟可接受
        estimated_latency = self.total_docs_tokens / 10_000  # 粗估
        if estimated_latency > self.max_acceptable_latency:
            return False, f"预计延迟{estimated_latency:.0f}s > {self.max_acceptable_latency}s"

        # 条件5：成本可接受
        estimated_cost = self.total_docs_tokens / 1_000_000 * 1.25  # Gemini 1.5 Pro
        if estimated_cost > self.budget_per_query:
            return False, f"预计成本${estimated_cost:.2f} > 预算${self.budget_per_query}"

        return True, "满足长上下文条件"


# 使用示例
criteria = LongContextCriteria(
    total_docs_tokens=80_000,        # 8万 Token
    query_frequency=5,                # 每天 5 次
    doc_update_frequency="monthly",   # 月度更新
    need_cross_doc_reasoning=True,    # 需要跨文档分析
    max_acceptable_latency=10.0,      # 10 秒可接受
    budget_per_query=0.50,            # $0.50/查询
)
use_lc, reason = criteria.should_use_long_context()
# → True, "满足长上下文条件"
```

### 何时用 RAG

```
用 RAG 的场景：
  - 文档量大（超出任何上下文窗口）
  - 查询频率高（每天 > 100 次）
  - 文档频繁更新
  - 需要精确引用溯源
  - 成本敏感
  - 需要高并发
  - 文档类型多样（PDF/HTML/数据库）
```

### 决策流程图

```python
def choose_strategy(doc_tokens: int, daily_queries: int,
                    need_cross_ref: bool, budget: float) -> str:
    """选择策略"""
    # 小文档 + 低频 + 需要跨文档推理 → 长上下文
    if doc_tokens < 100_000 and daily_queries < 50 and need_cross_ref:
        if doc_tokens / 1_000_000 * 3.0 * daily_queries < budget:
            return "long_context"

    # 大文档 → RAG
    if doc_tokens > 200_000:
        return "rag"

    # 中等文档 + 高频 → RAG
    if daily_queries > 100:
        return "rag"

    # 中等文档 + 低频 + 不需要跨文档 → RAG
    if not need_cross_ref:
        return "rag"

    # 混合
    return "hybrid"
```

## 4. 混合策略：长上下文 + RAG

### 架构设计

```
用户提问
  ↓
RAG 检索 Top-K（粗筛，5-10 篇）
  ↓
长上下文模型处理（精读检索到的文档）
  ↓
生成回答（有全文上下文 + 检索片段）

优势：
  - RAG 解决成本问题（只送相关文档）
  - 长上下文解决覆盖问题（完整文档不截断）
  - 结合两者优势
```

### 实现方案

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

@dataclass
class HybridStrategy:
    """RAG 粗筛 + 长上下文精读"""
    retriever: object         # 向量检索器
    long_context_model: str   # 长上下文模型
    top_k: int = 5            # 检索数量
    max_doc_tokens: int = 50000  # 单次最大 Token

    async def retrieve_and_read(self, query: str) -> dict:
        """检索 + 长上下文精读"""

        # 步骤1：RAG 粗筛
        docs = await self.retriever.ainvoke(query, top_k=self.top_k)

        # 步骤2：拼接完整文档（不截断）
        full_context = "\n\n---\n\n".join([
            f"文档 {i+1}: {doc.metadata.get('source', '未知')}\n{doc.page_content}"
            for i, doc in enumerate(docs)
        ])

        # 步骤3：估算 Token 数
        est_tokens = len(full_context) // 3  # 粗估
        if est_tokens > self.max_doc_tokens:
            # 超限：降级到截断模式
            full_context = full_context[:self.max_doc_tokens * 3]
            truncated = True
        else:
            truncated = False

        # 步骤4：长上下文模型精读
        prompt = ChatPromptTemplate.from_messages([
            ("system", """你是文档分析专家。以下是检索到的完整文档：

{context}

请仔细阅读所有文档，综合分析后回答用户问题。
{truncation_note}"""),
            ("human", "{query}")
        ])

        model = ChatOpenAI(model=self.long_context_model, temperature=0)
        chain = prompt | model

        response = await chain.ainvoke({
            "context": full_context,
            "query": query,
            "truncation_note": "注意：文档因长度限制被截断" if truncated else ""
        })

        return {
            "answer": response.content,
            "docs_used": len(docs),
            "truncated": truncated,
            "est_tokens": est_tokens,
        }
```

### 自适应策略切换

```python
class AdaptiveContextStrategy:
    """根据文档库大小和查询特征自适应选择策略"""

    def __init__(self, retriever, models: dict):
        self.retriever = retriever
        self.models = models  # {"fast": "gpt-4o-mini", "long": "gemini-1.5-pro", "standard": "gpt-4o"}
        self.doc_cache = {}   # 文档缓存（小型文档库）

    async def answer(self, query: str, doc_count: int, total_tokens: int):
        """自适应回答"""
        strategy = self.select_strategy(doc_count, total_tokens, query)

        if strategy == "long_context":
            return await self._long_context_answer(query)
        elif strategy == "rag":
            return await self._rag_answer(query)
        else:  # hybrid
            return await self._hybrid_answer(query)

    def select_strategy(self, doc_count: int, total_tokens: int, query: str):
        """选择策略"""
        # 小型文档库（< 5万 Token）→ 长上下文
        if total_tokens < 50_000:
            return "long_context"

        # 大型文档库（> 20万 Token）→ RAG
        if total_tokens > 200_000:
            return "rag"

        # 中型文档库 → 混合
        return "hybrid"

    async def _long_context_answer(self, query: str):
        """长上下文方案：全文档塞入"""
        docs = self.doc_cache.get("all_docs", "")
        model = ChatOpenAI(model=self.models["long"], temperature=0)
        response = await model.ainvoke(f"文档:\n{docs}\n\n问题: {query}")
        return {"answer": response.content, "strategy": "long_context"}

    async def _rag_answer(self, query: str):
        """RAG 方案"""
        docs = await self.retriever.ainvoke(query, top_k=5)
        context = "\n".join([d.page_content for d in docs])
        model = ChatOpenAI(model=self.models["standard"], temperature=0)
        response = await model.ainvoke(f"文档:\n{context}\n\n问题: {query}")
        return {"answer": response.content, "strategy": "rag", "sources": len(docs)}

    async def _hybrid_answer(self, query: str):
        """混合方案：RAG 检索 + 长上下文精读"""
        docs = await self.retriever.ainvoke(query, top_k=10)
        context = "\n\n".join([d.page_content for d in docs])
        model = ChatOpenAI(model=self.models["long"], temperature=0)
        response = await model.ainvoke(f"文档:\n{context}\n\n问题: {query}")
        return {"answer": response.content, "strategy": "hybrid", "sources": len(docs)}
```

## 5. 成本模型与优化

### 成本计算器

```python
@dataclass
class ContextCostCalculator:
    """长上下文 vs RAG 成本计算器"""
    model_pricing: dict = None

    def __post_init__(self):
        self.model_pricing = {
            "gemini-1.5-pro": {"input": 1.25, "output": 5.00},
            "gemini-2.0-flash": {"input": 0.10, "output": 0.40},
            "gpt-4o": {"input": 2.50, "output": 10.00},
            "gpt-4o-mini": {"input": 0.15, "output": 0.60},
            "claude-3.5-sonnet": {"input": 3.00, "output": 15.00},
        }

    def long_context_cost(self, model: str, doc_tokens: int,
                          output_tokens: int = 500) -> float:
        """长上下文方案成本"""
        pricing = self.model_pricing[model]
        input_cost = doc_tokens / 1_000_000 * pricing["input"]
        output_cost = output_tokens / 1_000_000 * pricing["output"]
        return input_cost + output_cost

    def rag_cost(self, model: str, retrieved_tokens: int,
                 output_tokens: int = 500, embedding_cost: float = 0.001) -> float:
        """RAG 方案成本"""
        pricing = self.model_pricing[model]
        input_cost = retrieved_tokens / 1_000_000 * pricing["input"]
        output_cost = output_tokens / 1_000_000 * pricing["output"]
        return input_cost + output_cost + embedding_cost

    def daily_cost(self, cost_per_query: float, daily_queries: int) -> float:
        """日成本"""
        return cost_per_query * daily_queries

    def break_even_analysis(self, model: str, total_doc_tokens: int,
                            avg_retrieved_tokens: int, daily_queries: int) -> dict:
        """盈亏平衡分析"""
        lc_cost = self.long_context_cost(model, total_doc_tokens)
        rag_cost = self.rag_cost(model, avg_retrieved_tokens)

        return {
            "long_context_daily": self.daily_cost(lc_cost, daily_queries),
            "rag_daily": self.daily_cost(rag_cost, daily_queries),
            "ratio": lc_cost / rag_cost if rag_cost > 0 else float("inf"),
            "cheaper": "rag" if rag_cost < lc_cost else "long_context",
        }


# 使用
calc = ContextCostCalculator()

# 场景：10万 Token 文档库，每天 500 次查询
result = calc.break_even_analysis(
    model="gpt-4o",
    total_doc_tokens=100_000,
    avg_retrieved_tokens=10_000,  # RAG 检索 1 万 Token
    daily_queries=500,
)
# long_context_daily: ~$137.5
# rag_daily: ~$14.3
# ratio: ~9.6x
# cheaper: rag
```

## 6. 实际场景分析

### 场景 1：法律合同审查

```
文档：1 份合同，约 3 万字（~4 万 Token）
查询频率：低（人工触发）
需要跨文档推理：否（单文档深度分析）
→ 长上下文方案
→ 模型：Claude 3.5 Sonnet（20万窗口）
→ 成本：~$0.12/次（可接受）
```

### 场景 2：客服知识库

```
文档：5000 篇 FAQ，总计约 500 万 Token
查询频率：高（每天 5000 次）
需要跨文档推理：否
→ RAG 方案
→ 模型：GPT-4o-mini
→ 成本：~$0.003/次（$15/天）
→ 长上下文方案成本：~$6,250/天（不可接受）
```

### 场景 3：研究论文分析

```
文档：20 篇论文，总计约 40 万 Token
查询频率：中（每天 50 次）
需要跨文档推理：是（对比不同论文观点）
→ 混合方案：RAG 检索 Top-10 + 长上下文精读
→ 模型：Gemini 1.5 Pro（200万窗口）
→ 成本：~$0.55/次（$27.5/天）
```

### 场景 4：代码库问答

```
文档：整个代码仓库，约 200 万 Token
查询频率：高（开发者每天查询）
需要跨文档推理：有时
→ RAG 方案（代码分块索引）
→ 模型：GPT-4o
→ 适当增大 Top-K（代码理解需要更多上下文）
```
