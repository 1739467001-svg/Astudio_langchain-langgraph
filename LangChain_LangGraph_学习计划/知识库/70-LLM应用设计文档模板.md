## 二、设计文档模板

```markdown
# [项目名称] 设计文档

## 1. 概述
- **目标**: 一句话描述要解决什么问题
- **用户**: 谁用这个应用（内部员工/外部客户/开发者）
- **场景**: 核心使用场景（2-3个）

## 2. 需求分析
### 2.1 功能需求
- [ ] 功能1: ...
- [ ] 功能2: ...
### 2.2 非功能需求
- 延迟: P95 < ?s
- 日调用量: ?
- 准确率: ≥ ?%
- 成本预算: $?/月

## 3. 架构设计
### 3.1 整体架构
（Mermaid架构图）

### 3.2 技术选型
| 组件 | 选择 | 理由 |
|------|------|------|
| 模型 | | |
| 向量库 | | |
| 框架 | | |
| 部署 | | |

### 3.3 设计模式
- 使用了哪些模式（Router/RAG/Agent/Guardrail）
- 为什么选择这些模式

## 4. 数据设计
### 4.1 知识库
- 文档来源: ?
- 文档量: ?篇
- 更新频率: ?

### 4.2 对话历史
- 存储方式: ?
- 保留期限: ?

## 5. 安全设计
- [ ] 输入护栏
- [ ] 输出护栏
- [ ] PII脱敏
- [ ] 速率限制
- [ ] 用户鉴权

## 6. 监控设计
- [ ] LangSmith追踪
- [ ] Token统计
- [ ] 错误告警
- [ ] 满意度收集

## 7. 测试计划
- 测试集: ?个问答对
- 评估方式: 规则+LLM+人工
- 通过标准: 准确率≥?%

## 8. 部署计划
- 部署方式: Docker/...
- 环境配置: .env / ...
- 回滚方案: ?

## 9. 风险与缓解
| 风险 | 概率 | 影响 | 缓解方案 |
|------|------|------|---------|
| API限流 | 中 | 高 | 缓存+备用模型 |
| 幻觉 | 中 | 高 | 约束+低temperature |
| 成本超支 | 低 | 中 | max_tokens+监控 |
```

## 三、完整示例

```markdown
# 智能客服助手 设计文档

## 1. 概述
- 目标: 为电商用户提供7x24小时智能客服
- 用户: 外部客户
- 场景: 订单查询、产品咨询、售后问题

## 2. 需求
- 延迟P95 < 5s
- 日调用量 ~2000次
- 准确率 ≥ 85%
- 成本 < $50/月

## 3. 架构
- 模式: Router(意图路由) + RAG(FAQ) + Agent(订单查询)
- 模型: GPT-4o-mini
- 向量库: FAISS
- 部署: Docker + FastAPI

## 4. 安全
- 双层护栏
- PII脱敏
- 10次/分钟限流

## 5. 测试
- 30个测试问答对
- 准确率≥85%方可上线
```

## 四、使用建议

| 阶段 | 文档用法 |
|------|---------|
| 启动前 | 填写设计文档，团队评审 |
| 开发中 | 对照设计文档实现 |
| 测试时 | 用设计文档的验收标准检查 |
| 上线后 | 设计文档作为维护参考 |
| 迭代时 | 更新设计文档记录变更 |
