# LLM 应用全链路压测与性能基准图解

> 全链路压测模拟真实用户行为——并发请求、混合场景、逐步加压、长时间持续——找出系统的降级点和崩溃点。

---

```mermaid
graph TB
    subgraph "压测阶段"
        PLAN["压测计划<br/>场景/目标/加压策略"] --> SETUP["环境准备<br/>数据+监控"]
        SETUP --> WARM["预热阶段<br/>逐步加压"]
        WARM --> PEAK["峰值阶段<br/>目标负载"]
        PEAK --> HOLD["持续阶段<br/>长时间保持"]
        HOLD --> STRESS["极限阶段<br/>超预期加压"]
        STRESS --> RECOVER["恢复阶段<br/>观察恢复"]
    end

    subgraph "混合场景"
        S1["简单问答 50%"]
        S2["RAG 检索 25%"]
        S3["多步推理 15%"]
        S4["工具调用 7%"]
        S5["流式输出 3%"]
    end

    subgraph "关键指标"
        PEAK --> M1["P50/P95/P99 延迟"]
        PEAK --> M2["吞吐量 QPS"]
        PEAK --> M3["错误率"]
        HOLD --> M4["内存泄漏"]
        HOLD --> M5["连接池耗尽"]
        STRESS --> M6["崩溃点"]
    end

    style WARM fill:#E3F2FD,stroke:#1565C0
    style PEAK fill:#E8F5E9,stroke:#2E7D32
    style HOLD fill:#FFF9C4,stroke:#F9A825
    style STRESS fill:#FFCDD2,stroke:#C62828
    style RECOVER fill:#E8F5E9,stroke:#2E7D32
```

---

## 加压策略对比

| 策略 | 方式 | 目的 |
|------|------|------|
| 阶梯加压 | 10→50→100→200 QPS | 找拐点 |
| 恒定负载 | 固定 QPS 持续 30min | 测稳定性 |
| 脉冲突发 | 瞬间 10x 流量 | 测弹性 |
| 长时间跑 | 低负载 24h | 测内存泄漏 |

## 性能基准基线

| 指标 | 基线值 | 告警阈值 |
|------|--------|----------|
| P50 延迟 | 500ms | > 1s |
| P95 延迟 | 2s | > 5s |
| P99 延迟 | 5s | > 10s |
| QPS | 100 | < 50 |
| 错误率 | 0.1% | > 1% |
| GPU 利用率 | 70% | > 90% |
