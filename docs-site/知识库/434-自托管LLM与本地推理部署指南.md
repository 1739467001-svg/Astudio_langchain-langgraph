# 自托管 LLM 与本地推理部署指南

> 不是所有场景都能用 OpenAI API——数据隐私要求、成本控制、离线场景、定制化需求都需要自己部署模型。vLLM、Ollama、llama.cpp 各有优劣。本指南系统讲解自托管 LLM 的推理引擎选型、部署方案、与 LangChain 的集成，以及性能调优。

---

## 1. 为什么要自托管

### 自托管的驱动力

```
场景 1：数据隐私
  医疗/金融/法律行业，数据不能离开内网
  → 必须本地部署

场景 2：成本控制
  日均 100 万次调用，OpenAI 月费 $5万+
  自托管同等算力月费 $1万
  → 6 个月内收回硬件投资

场景 3：低延迟
  实时对话要求 < 200ms 首 Token
  云 API 网络延迟 100-300ms
  本地推理 < 50ms
  → 本地部署

场景 4：离线场景
  无网络环境或网络不稳定
  → 必须本地部署

场景 5：定制化
  需要微调模型、自定义分词器、特殊解码策略
  → 本地部署
```

### 云 API vs 自托管对比

| 维度 | 云 API（OpenAI/Anthropic） | 自托管（vLLM/Ollama） |
|------|--------------------------|---------------------|
| 初始成本 | 零 | GPU 硬件/租赁 |
| 边际成本 | 按量计费 | 固定成本（电+折旧） |
| 模型质量 | 最高（GPT-4o/Claude） | 中等（开源模型） |
| 延迟 | 100-500ms | 10-100ms |
| 数据隐私 | 数据需离开本地 | 数据不离开内网 |
| 可控性 | 低（厂商随时变更） | 高 |
| 运维 | 零 | 需要 GPU 运维 |
| 扩展性 | 弹性扩展 | 需扩容硬件 |
| 模型选择 | 有限（厂商提供） | 丰富（HuggingFace 全库） |

## 2. 推理引擎选型

### 主流推理引擎对比

| 引擎 | 定位 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| vLLM | 高性能服务 | PagedAttention、高吞吐 | 部署复杂、需 GPU | 生产环境大规模 |
| Ollama | 简易部署 | 一行命令、跨平台 | 性能一般 | 开发/个人/小规模 |
| llama.cpp | 极致轻量 | CPU 可跑、量化好 | 性能最低 | 边缘设备/无 GPU |
| TGI (HuggingFace) | 企业级 | 功能全、HF 集成 | 重、启动慢 | 企业生产 |
| SGLang | 前沿研究 | 最快推理、结构化 | 较新、文档少 | 研究实验 |
| TensorRT-LLM | NVIDIA 极致优化 | 最快（NVIDIA GPU） | 仅 NVIDIA、复杂 | 极致性能 |

### 选型决策树

```
有 GPU 吗？
├─ 有 → 生产环境？
│   ├─ 是 → vLLM（高吞吐 + 兼容 OpenAI API）
│   └─ 否 → Ollama（简单易用）
├─ 没有 → 内存够大（>16GB）？
│   ├─ 是 → Ollama（CPU 模式）
│   └─ 否 → llama.cpp（极致轻量）
└─ 有 NVIDIA GPU + 追求极致性能 → TensorRT-LLM
```

## 3. vLLM 部署指南

### 安装与启动

```bash
# 安装
pip install vllm

# 基本启动（OpenAI 兼容 API）
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --port 8000 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.9 \
  --tensor-parallel-size 1

# 常用参数
# --model: HuggingFace 模型名或本地路径
# --port: API 端口
# --max-model-len: 最大上下文长度
# --gpu-memory-utilization: GPU 显存利用率（0-1）
# --tensor-parallel-size: 多 GPU 并行数
# --quantization: 量化方式（awq, gptq, fp8）
# --enable-lora: 启用 LoRA 适配器
# --served-model-name: API 中的模型名
```

### 在 LangChain 中使用 vLLM

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

# vLLM 提供 OpenAI 兼容 API，直接用 ChatOpenAI 连接
llm = ChatOpenAI(
    model="Qwen/Qwen2.5-7B-Instruct",  # 与启动时的模型名一致
    openai_api_base="http://localhost:8000/v1",
    openai_api_key="not-needed",  # vLLM 默认不验证
    temperature=0.7,
    max_tokens=1024,
)

# 像使用 OpenAI 一样使用
response = llm.invoke("用 Python 实现快速排序")
print(response.content)

# 流式输出
async for chunk in llm.astream("解释 RAG 的原理"):
    print(chunk.content, end="", flush=True)

# 工具调用（需要模型支持）
from langchain_core.tools import tool

@tool
def calculate(expression: str) -> str:
    """计算数学表达式"""
    try:
        return str(eval(expression))
    except:
        return "计算错误"

# 注意：不是所有开源模型都支持工具调用
# Qwen2.5-Instruct / Llama 3.1 / Mistral 支持工具调用
tool_llm = llm.bind_tools([calculate)
```

### Ollama + LangGraph 完整 Agent

```python
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode
from langchain_ollama import ChatOllama
from langchain_core.tools import tool

@tool
def web_search(query: str) -> str:
    """搜索网络"""
    # 实际使用 duckduckgo 或其他搜索
    return f"搜索结果: &#123;query&#125;"

@tool
def calculator(expression: str) -> str:
    """计算"""
    return str(eval(expression))

# Ollama 模型绑定工具
llm = ChatOllama(model="qwen2.5:14b", temperature=0)
tool_llm = llm.bind_tools([web_search, calculator])

async def agent_node(state: MessagesState):
    response = await tool_llm.ainvoke(state["messages"])
    return &#123;"messages": [response]&#125;

def should_use_tool(state: MessagesState):
    last_msg = state["messages"][-1]
    if hasattr(last_msg, "tool_calls") and last_msg.tool_calls:
        return "tools"
    return END

graph = StateGraph(MessagesState)
graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode([web_search, calculator]))
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_use_tool, &#123;"tools": "tools", END: END&#125;)
graph.add_edge("tools", "agent")

# 完全本地化的 Agent
local_agent = graph.compile()
```

## 6. 性能调优

### vLLM 性能优化

```python
# === 关键参数调优 ===

# 1. PagedAttention（默认开启）
# vLLM 的核心技术，自动管理 KV Cache 内存
# 无需手动配置

# 2. Continuous Batching（默认开启）
# 动态拼接请求，提高 GPU 利用率
# 无需手动配置

# 3. GPU 显存利用率
# 默认 0.9，生产环境可调到 0.95
# 但要留余量防止 OOM
vllm serve ... --gpu-memory-utilization 0.95

# 4. 最大序列数（影响并发）
vllm serve ... --max-num-seqs 256  # 默认 256

# 5. 量化（减少显存+加速）
# AWQ: 精度损失小，速度提升明显
vllm serve ... --quantization awq

# 6. 指定 GPU
CUDA_VISIBLE_DEVICES=0 vllm serve ...

# 7. 多 GPU 张量并行
vllm serve ... --tensor-parallel-size 2

# 8. KV Cache 量化（进一步省显存）
vllm serve ... --kv-cache-dtype fp8  # 需要 H100/A100
```

### 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| OOM（显存不足） | 模型太大或 max_model_len 过大 | 量化模型或减小 max_model_len |
| 首 Token 延迟高 | 模型加载/预热 | 保持模型常驻内存 |
| 吞吐量低 | 并发不够/batch 太小 | 增大 max_num_seqs |
| 量化后精度下降 | 量化方式选择 | AWQ > GPTQ > INT4 |
| 偶尔超时 | GPU 温度过高降频 | 改善散热/降频运行 |
| 工具调用失败 | 模型不支持/格式错误 | 确认模型支持 function calling |

## 8. 混合部署架构

### 云 + 本地混合

```python
from dataclasses import dataclass
from langchain_openai import ChatOpenAI

@dataclass
class HybridLLMRouter:
    """混合模型路由器"""

    # 本地模型（免费/低延迟/隐私）
    local_model = ChatOpenAI(
        model="Qwen2.5-7B-Instruct",
        openai_api_base="http://localhost:8000/v1",
        openai_api_key="not-needed",
    )

    # 云端模型（高质量/贵）
    cloud_model = ChatOpenAI(model="gpt-4o")

    async def route(self, query: str, require_privacy: bool = False,
                    require_high_quality: bool = False):
        """路由决策"""
        if require_privacy:
            return self.local_model  # 隐私数据必须本地
        if require_high_quality:
            return self.cloud_model  # 高质量用云端
        if len(query) < 100:
            return self.local_model  # 简单问题本地
        return self.cloud_model  # 复杂问题云端
```
